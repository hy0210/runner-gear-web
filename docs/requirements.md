# 需求與評分標準摘要

依六角學院「單人專題審核說明文件｜前後端整合主題電商平台（2026 企業專題班）」整理。
需求來源：<https://polar-client-338.notion.site/2026-3f96e9dba9138040a565c63bb58e84bb>。本文件與原文有出入時，以原文為準。

- 主題：跑步裝備店（Runner Gear 跑者裝備），學員可自訂電商主題
- 繳交期限：**2026/11/24（二）23:59**，寄至 homework@hexschool.com
- 審核期間：**2026/11/13 起至 2026/12/04**，前後端都須正常運作；期間無法連線視同未完成
- 及格標準：總分 ≥ 70，且後端、前端各自 ≥ 24 分
- API 設計、資料庫結構、頁面細節與元件拆分皆可自行規劃

## 不予評分的條件（任一成立即不予評分）
- 前端網址無法連線
- 後端網址無法連線
- Repo 無法存取
- 缺少 API 文件

## 技術限制

**後端**
- Node.js + Express；資料庫與 ORM 不限
- 落實 MVC：路由、控制邏輯、資料模型的職責分開
- 機密資料（環境變數、連線字串）不可出現在程式碼或版本紀錄中

**前端**
- Vite + Vue 3（Composition API），搭配任一 CSS 框架（本專題用 Bootstrap 5）
- 元件合理拆分，使用正確的 HTML5 語意標籤
- **不可使用假資料或 JSON Server**，所有資料必須來自自己的後端 API

**部署**
- 前端、後端放在獨立的 GitHub Repo，各自部署到雲端並實際串接
- 前端提供可公開連線的網站網址；後端提供可公開呼叫的 API Base URL（可用 Postman 測試）

## 後端功能需求
- **會員**：註冊、登入；密碼不可明文儲存；登入成功以 JWT 發行 Token
- **權限**：區分一般會員與管理員，一般會員不能以任何方式升級為管理員；管理員帳號的產生方式自行規劃並於提交時說明
- **商品**：所有人可瀏覽商品列表與單一商品；列表支援分頁、分類篩選、關鍵字搜尋
- **商品管理（管理員）**：新增、編輯、刪除商品。**只要求 API，不強制製作後台管理頁面**
- **購物車**：登入會員可加入、調整數量、移除、查看；需處理邊界情況（重複加入、商品不存在、數量不合理等）

## 前端功能需求
- **頁面**：至少包含首頁、商品列表頁、登入與註冊頁、購物車介面（Offcanvas、Modal 或獨立頁面皆可）
- **RWD**：所有頁面在手機與桌機都有合理的版面
- **商品列表**：資料來自後端 API；可依分類篩選、以關鍵字搜尋，並支援分頁或其他合理的分批載入；載入中、查無結果、API 錯誤時都要有提示
- **會員**：可註冊與登入；重新整理後仍維持登入；提供登出
- **未登入加入購物車**：要有合理的處理方式或引導
- **購物車（重點檢核）**：加入、增減數量、移除後**必須與後端資料同步**；加入購物車時給予明確的操作回饋

## 繳交內容
1. 程式勇者村帳號（email）
2. 前端、後端 GitHub Repo：**commit 紀錄需能看出開發過程**
3. 前後端部署網址
4. README 或文件：專案主題、選用技術、本機啟動方式、環境變數、一般會員與管理員的測試帳號（以及管理員產生方式）
5. API 文件（OpenAPI、Postman 或 Swagger）：審核者不看程式碼也知道如何呼叫每支 API
6. 測試資料：資料庫中有足以展示分頁、分類與搜尋的商品
