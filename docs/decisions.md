# 決策紀錄

agent 自行決定的事項與理由，一行一條。使用者回答過的決策也記在這裡（標「使用者」）。

| 日期 | 相關 issue | 決定 | 理由 |
|---|---|---|---|
| 11/16 | 流程 | 【使用者】開發前先畫 wireframe 並經確認；畫面依 wireframe 實作 | 使用者指示 |
| 11/16 | #1 | 【使用者】配色維持 wireframe 的灰階（黑、白、灰），不另外設定主色 | 使用者偏好 |
| 11/16 | #3 | 【使用者】首頁標語「跑得更遠，從一雙合腳的鞋開始」；精選商品桌機 8 筆 | 使用者採建議 |
| 11/16 | #1 | Vite 8、Vue 3.5、Vue Router 5、Pinia 4、axios、Bootstrap 5.3；JavaScript、ES Module | 計畫指定的技術組合，取目前的穩定版 |
| 11/16 | #1 | 直接使用 Bootstrap 編譯好的 CSS，以深色按鈕與少量自訂 CSS 呈現灰階，不引入 Sass | 少一個建置相依；灰階不需要改主題變數 |
| 11/16 | #1 | Bootstrap 的 JS 只載入用到的元件（Collapse、Offcanvas、Toast） | 減少打包體積 |
| 11/16 | #1 | `VITE_API_BASE_URL` 在開發與建置時必填，缺少就直接失敗；CI 會驗證這一點 | 避免部署出連不到後端的網站 |
| 11/16 | #1 | 只有「帶著 Token 的請求得到 401」才會自動登出並導向登入頁 | 登入時帳密錯誤也是 401，不應被當成 Token 失效 |
| 11/16 | #1 | Token 與會員資料存在 localStorage（鍵名 `runner-gear.session`） | 需求要求重新整理後維持登入；沒有 refresh token。代價是 XSS 時可被讀取，因此全站禁用 `v-html` |
| 11/16 | #1 | 測試用 Vitest + Vue Test Utils + jsdom，API 以 mock 取代 | 計畫指定；前端測試不依賴後端服務 |
| 11/16 | #1 | CI 工作名稱為 `lint-test-build` 與 `security-scan` | 設定 `main` 保護規則時勾選這兩個 |
| 11/16 | #2 | 手機版選單的展開收合由 Vue 的狀態控制，不載入 Bootstrap 的 Collapse JS | 行為簡單，且容易測試 |
| 11/16 | #3 | 首頁主視覺只放文字，不放圖片 | 沒有可用的自有圖片；避免再依賴外部圖片服務 |
| 11/16 | #3 | 精選商品取商品列表的前 8 筆（`limit=8`） | 後端沒有「精選」欄位；需求只要求資料來自 API |
| 11/16 | #4 | 篩選條件與頁碼以網址的查詢參數為準（`categoryId`、`keyword`、`page`） | 重新整理可還原、連結可分享；上一頁也能正確返回 |
| 11/16 | #4 | 每頁 12 筆；桌機 4 欄、平板 3 欄、手機 2 欄 | 與後端預設一致；各寬度都排得整齊 |
| 11/16 | #4 | 分類載入失敗時仍顯示商品，只是沒有分類按鈕 | 次要資料失敗不應擋住主要內容 |
| 11/16 | #4 | 連續切換條件時只採用最後一次查詢的結果 | 避免較慢的舊請求蓋掉新的結果 |
| 11/16 | #5 | 登入與註冊的請求標記 `skipAuth`：不帶舊 Token，失敗的 401 也不觸發自動登出 | 資安審查批次 5 第 2 項 |
| 11/16 | #5 | 登入後的 `redirect` 只接受以單一 `/` 開頭的站內路徑，其餘一律回首頁 | 避免開放重新導向（資安審查批次 5 第 3 項） |
| 11/16 | #5 | 註冊成功直接成為登入狀態 | 後端註冊即回傳 Token，少一步操作 |
| 11/16 | #5 | 已登入時開啟登入、註冊頁會導向首頁 | 避免重複登入造成混淆 |
| 11/16 | #5 | 登入表單只檢查有無填寫，註冊表單才檢查密碼長度 | 登入時沿用後端的單一錯誤訊息即可 |
| 11/16 | #5 | 每次送出後都清空密碼欄位 | 密碼不留在畫面與記憶體 |
| 11/16 | #5 | 啟動時若有 Token，呼叫 `GET /auth/me` 確認仍有效並更新會員資料 | 重新整理後的登入狀態以後端為準 |
| 11/16 | #6 | 購物車以 Offcanvas 呈現；開關、焦點與 Esc 由 Vue 控制，不載入 Bootstrap 的 Offcanvas JS | 行為單純、容易測試；開啟時焦點移到關閉按鈕 |
| 11/16 | #6 | 購物車跟著登入狀態：有 Token 時（含重新整理後）向後端取得，登出或 Token 失效時清空 | 購物車內容一律以後端為準 |
| 11/16 | #6 | 數量以 − / + 按鈕調整，範圍 1–99；要歸零請按「移除」 | 與後端的限制一致，避免誤刪 |
| 11/16 | #6 | 操作失敗時只顯示提示，畫面只由後端的回應更新 | 不做樂觀更新，畫面不會與後端不一致 |
| 11/16 | #6 | 未登入點「加入購物車」或購物車按鈕：提示「請先登入」並導向登入頁，登入後回到原頁 | 需求要求未登入時要有引導 |
| 11/16 | #6 | 提示訊息（Toast）固定在右下角，3.5 秒後自動消失，可手動關閉 | 加入購物車的操作回饋 |
| 11/16 | #6 | 購物車不提供結帳按鈕，並註明「不提供結帳功能」 | 需求不含訂單與結帳 |
